| **№** | **Требование** |
|---|------------|
| 1 | Ежедневная синхронизация ставок без задержек; автоматизация генерации файлов в АБС. |
| 2 | Безопасная передача файлов (SFTP для партнера; шифрование). |
| 3 | Доступность 24/7 с 99.9% uptime; резервный ЦОД для интеграций. |
| 4 | Использование существующих технологий (Oracle в АБС, Java в кол-центре); миграция ставок из XLS в АБС. |
| 5 | Масштабируемость для увеличения звонков; горизонтальное для кол-центра, вертикальное для АБС. |
| 6 | Документация интеграций; экспертиза в банке для поддержки. |
| 7 | Минимальные изменения в системах; избегание API для партнера (только файлы). |

Для новых изменений предлагается последовательная интеграция: сначала миграция ставок в АБС, затем автоматизация генерации/передачи файлов в кол-центр банка и партнеру. Логика выбора:
- **Функциональные аспекты**: Начать с АБС как центрального хранилища ставок (миграция из XLS для автоматизации). Передача в кол-центр банка через внутреннюю интеграцию Kafka, так как ее наличие вытикает уже из задания3, партнеру — через SFTP-файлы (без API). 
- **Нефункциональные аспекты**: Ежедневный cron-job или другой планировщик в АБС для генерации файлов; шифрование для безопасности. Используем существующие технологии (PL-SQL для генерации в АБС, Java для кол-центра)

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

 **Внешний сервис для ставок**: Хранить ставки в облаке.Но нет компетенций, несоответствие требованию использовать внутренние системы и проблемы безопасности.
 
 **Доступ сторонним сотрудникам**: Предоставить ограниченный доступ к внутренней системе для просмотра ставок.


**Недостатки, ограничения, риски**

- **Недостатки**: Файловая передача (SFTP) не realtime — задержки в обновлениях ставок; ручная миграция из XLS может вызвать ошибки. 
- **Ограничения**: АБС перегружен — добавление генерации файлов увеличивает нагрузку; партнер зависит от файлов, нет автоматизации на их стороне.

### <a name="_bjrr7veeh80c"></a>**Список крупных задач для каждой системы**

- **АБС**:
  1. Миграция хранения ставок из XLS в БД Oracle.
  2. Интеграция с кол-центром банка для передачи данных (Java-расширения).
  3. Настройка SFTP для передачи файлов партнеру.
  4. Тестирование нагрузки и безопасности.

- **Система кол-центра (банка)**:
  1. Расширение на Java для приема и отображения ставок из АБС.
  2. Обновление интерфейса (React.js) для просмотра ставок менеджерами.
  3. Интеграция с мониторингом нагрузки для перенаправления звонков партнеру.
  4. Тестирование консультаций по ставкам.

- **Система партнерского кол-центра**:
  1. Настройка скачивания файлов с SFTP банка.
  2. Импорт ставок в их систему для отображения.
  3. Обучение сотрудников партнера работе со ставками.

- **Общие (IT/Трансформация)**:
  1. Разработка документации и мониторинга для всех интеграций.
  2. Тестирование end-to-end последовательности.
